# 芯知 SemiKB 接口设计

版本 v1.4 · 2026-11-20 · 与《01 架构设计》配套，已按实现校准
Base URL：`http://127.0.0.1:8010`

> 实现校准说明：实际代码路径以 `semikb/api` 与项目根 `README.md` 为准。用户问答 WebSocket 为 `/api/chat/ws/{session_id}`，管理端 WebSocket 为 `/api/admin/ws?token=...`，上传接口为 `POST /api/admin/documents/upload`，全量重建为 `POST /api/admin/rebuild`。问答页历史会话列表为 `GET /api/chat/sessions`，列表展示的 `conversation_id` 取该会话首条机器人消息的 id。问候、感谢、身份或能力询问走 `direct` 路由，只经过 `route_question` 与 `direct_answer`，不检索 Milvus，也不产生引用。

## 1. 通用约定

### 1.1 基础

| 项 | 约定 |
|---|---|
| 传输 | HTTP/1.1 与 WebSocket |
| 编码 | UTF-8 |
| 请求体 | `application/json`，上传接口用 `multipart/form-data` |
| 时间 | ISO 8601 带时区，例如 `2026-11-20T14:05:00+08:00` |
| 主键 | 数据库自增 id 用整数，文档标识 `doc_uid` 用 32 位十六进制字符串 |
| 字段命名 | 小写下划线，与 Pydantic 模型一致 |
| 接口前缀 | 业务接口 `/api`，问答长连接 `/api/chat/ws`，管理长连接 `/api/admin/ws` |

### 1.2 统一响应

所有 REST 接口返回同一结构，HTTP 状态码与 `code` 保持一致。

```json
{
  "code": 200,
  "message": "ok",
  "data": {}
}
```

`202` 表示任务已受理，`data` 里带 `task_id`。`data` 为空时返回 `null`，不省略字段。

### 1.3 错误码

| code | 含义 | 典型场景 |
|---|---|---|
| 200 | 成功 | 正常返回 |
| 202 | 已受理 | 上传、重建、删除进入队列 |
| 400 | 参数错误 | 问题为空、评分越界、分页参数非法 |
| 401 | 未认证 | 令牌缺失、过期、签名不符、密码错误 |
| 403 | 无权限 | 令牌有效但账号被停用 |
| 404 | 资源不存在 | 会话、消息、文档、任务不存在 |
| 409 | 状态冲突 | 文件重复、会话已有提问在进行、文档未就绪 |
| 413 | 文件过大 | 超过 5 MB |
| 415 | 类型不支持 | 非 Markdown 文件 |
| 429 | 触发限流 | 带 `Retry-After` 响应头 |
| 500 | 服务器内部错误 | 未捕获异常，堆栈只进日志 |
| 503 | 依赖不可用 | MySQL 或 Milvus 不可用 |
| 504 | 上游超时 | 大模型或整链路超过预算 |

错误响应示例：

```json
{"code": 429, "message": "发送过于频繁，请 8 秒后再试", "data": null}
```

### 1.4 鉴权

| 范围 | 方式 |
|---|---|
| 访客接口 | 无需鉴权，按 IP 与会话限流 |
| 管理端 REST | 请求头 `X-Admin-Token: <token>` |
| 管理端 WebSocket | 连接参数 `/api/admin/ws?token=<token>` |

令牌为无状态签名串，载荷含 `admin_id` 与 `exp`，服务端用 HMAC SHA256 校验，有效期 8 小时。登录后前端存 `localStorage`，每次请求自动带头。令牌缺失返回 401，签名错误返回 401，过期返回 401 并在 `message` 中提示重新登录。

不使用 Cookie，不存在 CSRF 问题。开发环境跨域由 Vite 代理解决，生产同源部署。

### 1.5 分页

查询参数 `page` 从 1 开始，`size` 默认 20，最大 100。响应统一为：

```json
{"items": [], "total": 0, "page": 1, "size": 20}
```

`total` 是满足过滤条件的总数，不是当前页条数。

### 1.6 限流

触发限流返回 429，并带 `Retry-After` 头，单位为秒。前端把该值显示在提示条里，倒计时结束前禁用发送按钮。

| 接口 | 阈值 |
|---|---|
| `POST /api/chat/sessions` | 每 IP 20 次每分钟 |
| WebSocket `chat` 消息 | 每会话 10 次每分钟 |
| `POST /api/admin/login` | 每 IP 5 次每分钟 |
| `POST /api/admin/retrieval-test` | 每管理员 30 次每分钟 |
| `POST /api/admin/qa-test` | 每管理员 10 次每分钟 |
| `POST /api/admin/documents/upload` | 每管理员每小时 30 个文件 |

### 1.7 幂等

| 操作 | 幂等策略 |
|---|---|
| 上传 | `file_hash` 唯一，重复上传返回 409 与已有 `doc_uid` |
| 评价 | 同一消息重复评价以最后一次为准 |
| 重建与删除 | 同一文档已有进行中的同类任务时返回 409，不重复排队 |
| 全量重建 | 已有进行中的重建任务时返回 409 |

### 1.8 版本

本期统一前缀 `/api`，不引入 `/v1`。`GET /api/meta` 返回 `api_version`，后续若出现破坏性变更再启用版本前缀。新增字段与新增枚举值视为兼容变更，前端应忽略未知字段。

## 3. 公共对象

### 3.1 SessionInfo

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | int | 会话 id |
| `visitor_name` | string | 访客昵称，默认 `访客` |
| `status` | string | `active` 或 `closed` |
| `turn_count` | int | 已完成问答轮数 |
| `created_at` | string | 创建时间 |
| `last_active_at` | string | 最后活动时间 |

### 3.2 ConversationInfo

| 字段 | 类型 | 说明 |
|---|---|---|
| `conversation_id` | int | 会话展示 id，等于该会话首条机器人消息的 `t_message.id` |
| `session_id` | int | 内部会话 id，用于历史消息与 WebSocket 接口 |
| `title` | string | 首条用户消息截断，作为列表标题 |
| `preview` | string | 首条机器人回答截断，作为回答预览 |
| `status` | string | `active` 或 `closed` |
| `turn_count` | int | 已完成问答轮数 |
| `message_count` | int | 会话消息总数 |
| `created_at` | string | 创建时间 |
| `updated_at` | string | 更新时间 |
| `last_active_at` | string | 最后活动时间 |

### 3.3 MessageInfo

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | int | 消息 id |
| `session_id` | int | 所属会话 |
| `role` | string | `user` 或 `bot` |
| `content` | string | 消息正文 |
| `source` | string\|null | `vectorstore`、`web_search`、`direct`、`fallback`、`extractive`，用户消息为 `null` |
| `route` | string\|null | `vectorstore`、`web_search` 或 `direct` |
| `sources` | SourceItem[] | 引用列表，用户消息为空数组 |
| `trace` | TraceInfo\|null | 节点时间线，用户消息为 `null` |
| `verified` | bool | 是否通过生成校验，用户消息恒为 `true` |
| `rating` | int\|null | `1` 或 `-1`，未评价为 `null` |
| `latency_ms` | int\|null | 本轮总耗时 |
| `created_at` | string | 创建时间 |

### 3.4 SourceItem

| 字段 | 类型 | 说明 |
|---|---|---|
| `doc_uid` | string\|null | 本地文档标识，联网来源为空 |
| `filename` | string\|null | 原文件名 |
| `title` | string\|null | 层级标题路径 |
| `chunk_index` | int\|null | 切片序号 |
| `url` | string\|null | 本地引用为 `/document/{doc_uid}`；联网引用为外部地址；无法定位时为空 |
| `score` | float\|null | 检索得分，RRF 融合分 |
| `snippet` | string | 片段摘录，最多 512 字符 |

本地引用不再把文件名当作 URL。`GET /document/{doc_uid}` 按 `t_document.source_path` 读取 Markdown 原文，转义后只读展示，文档删除、文件缺失或后缀不合法时返回 404 页面。历史引用读取时也会按 `doc_uid` 归一化为该路径，不需要迁移旧数据。

### 3.5 TraceInfo

| 字段 | 类型 | 说明 |
|---|---|---|
| `nodes` | object[] | 节点数组，元素含 `node`、`elapsed_ms`、`detail` |
| `rewrite_count` | int | 改写次数 |
| `regenerate_count` | int | 重新生成次数 |
| `llm_calls` | int | 本轮模型调用总数 |
| `latency_ms` | int | 整链路耗时 |
| `terminated_by` | string | `useful`、`direct`、`rewrite_exhausted`、`grounded_failed`、`llm_error`、`budget_exceeded`、`no_result` |

`nodes` 中 `detail` 的值随节点不同：

| 节点 | detail |
|---|---|
| `route_question` | `{"route":"vectorstore","method":"keyword"}` 或 `{"route":"direct","method":"small_talk","intent":"identity"}` |
| `direct_answer` | `{"intent":"identity","chars":89}` |
| `retrieve` | `{"hits":4}` |
| `grade_documents` | `{"kept":3,"total":4}` |
| `generate` | `{"chars":420}` |
| `grade_generation` | `{"grounded":"yes","answers_question":"no"}` |
| `transform_query` | `{"rewritten_question":"..."}` |
| `web_search` | `{"results":3}` |

### 3.6 DocumentInfo

| 字段 | 类型 | 说明 |
|---|---|---|

| `title` | string\|null | 文档主标题 |

## 4. 用户端接口

### 4.1 获取元信息

`GET /api/meta`

响应：

```json
{
  "code": 200,
  "message": "ok",
  "data": {
    "api_version": "1.0",
    "brand": {
      "name": "芯知 SemiKB",
      "slogan": "让每一份工艺文档都能被问出来",
      "org_name": "半导体文档知识库"
    },
    "suggestions": [
      "EUV 光刻胶的分辨率极限如何突破",
      "3D NAND 堆叠工艺的主要挑战是什么",
      "GAAFET 相比 FinFET 有哪些优势",
      "CMP 在先进制程中起什么作用"
    ],
    "features": {"citations": true, "trace": true, "web_search": true},
    "limits": {"question_max_chars": 2000}
  }
}
```

### 4.2 创建会话

`POST /api/chat/sessions`

请求：

```json
{"visitor_name": "工艺工程师"}
```

`visitor_name` 可省略，最长 32 字符。响应：

```json
{
  "code": 200,
  "message": "ok",
  "data": {
    "id": 12,
    "visitor_name": "工艺工程师",
    "status": "active",
    "turn_count": 0,
    "created_at": "2026-11-20T14:05:00+08:00",
    "last_active_at": "2026-11-20T14:05:00+08:00"
  }
}
```

错误：429 触发 IP 限流。

### 4.3 会话列表

`GET /api/chat/sessions?limit=50`

`limit` 取 1 到 100，默认 50。接口只返回至少有一条机器人回复的会话，按最后活动时间倒序排列。

列表中的 `conversation_id` 是该会话首条机器人消息的 `t_message.id`，同一会话内保持不变。`session_id` 是内部会话 id，历史消息与 WebSocket 仍使用它。

响应：

```json
{
  "code": 200,
  "message": "ok",
  "data": {
    "items": [
      {
        "conversation_id": 8,
        "session_id": 6,
        "visitor_name": "访客",
        "status": "active",
        "turn_count": 1,
        "title": "EUV 光刻胶的分辨率极限如何突破",
        "preview": "EUV光刻胶的分辨率极限突破主要通过材料创新路径实现...",
        "message_count": 2,
        "created_at": "2026-11-20T12:35:02+08:00",
        "updated_at": "2026-11-20T12:36:43+08:00",
        "last_active_at": "2026-11-20T12:36:43+08:00"
      }
    ],
    "total": 1,
    "limit": 50
  }
}
```

`total` 是所有可展示会话的总数，不受 `limit` 截断。

### 4.5 结束会话

`POST /api/chat/sessions/{id}/close`

响应 `data` 为更新后的 SessionInfo，`status` 变为 `closed`。已关闭的会话重复调用直接返回当前信息，不报错。关闭后 WebSocket 发送 `chat` 返回 400。

### 4.6 评价

`POST /api/chat/messages/{id}/rate`

请求：

```json
{"rating": 1}
```

`rating` 取 `1` 或 `-1`。只能评价 `role=bot` 的消息。响应：

```json
{"code": 200, "message": "ok", "data": {"message_id": 102, "rating": 1}}
```

错误：404 消息不存在或不是机器人消息。

## 5. WebSocket 问答

### 5.1 连接

`ws://127.0.0.1:8010/api/chat/ws/{session_id}`

连接建立后服务端立即下发：

```json
{"type": "ready", "data": {"session_id": 12, "status": "active"}}
```

会话不存在时服务端先下发 `error` 再以 1008 关闭。会话已关闭时仍可连接，但发送 `chat` 会被拒。

### 5.2 客户端消息

| type | 载荷 | 说明 |
|---|---|---|
| `chat` | `{"type":"chat","content":"...","debug":false}` | `content` 最长 2000 字符，`debug` 为真时节点事件保留更多细节，管理台调试用它 |
| `ping` | `{"type":"ping"}` | 30 秒一次心跳，服务端回 `pong` |

### 5.3 服务端事件

| type | 载荷 | 时机 |
|---|---|---|
| `ready` | `{"session_id","status"}` | 连接建立 |
| `user_message` | `{"message": MessageInfo}` | 用户消息落库后，作为写入确认 |
| `node` | `{"node","phase","elapsed_ms","detail"}` | 节点开始与结束，`phase` 为 `start` 或 `end` |
| `chunk` | `{"delta":"..."}` | 生成阶段逐 token 输出 |
| `message_end` | `{"message": MessageInfo}` | 回答完成并落库 |
| `session_status` | `{"status":"active"}` | 会话状态变化 |
| `error` | `{"code","message","retry_after"}` | 任何失败 |
| `pong` | `{}` | 心跳响应 |

`node` 事件的 `node` 取值与 trace 节点一致。`phase=start` 时 `elapsed_ms` 为 0，`detail` 为空对象；`phase=end` 带耗时与结果。

### 5.4 典型时序

```text
客户端                          服务端
  │ ── chat {"content":"EUV 光刻胶..."} ──▶
  │ ◀── user_message {id:101} ────────────
  │ ◀── node route_question start ─────────
  │ ◀── node route_question end {route:vectorstore,method:keyword}
  │ ◀── node retrieve start ───────────────
  │ ◀── node retrieve end {hits:4} ────────
  │ ◀── node grade_documents start ────────
  │ ◀── node grade_documents end {kept:3} ─
  │ ◀── node generate start ───────────────
  │ ◀── chunk {"delta":"主要"} ─────────────
  │ ◀── chunk {"delta":"受光子"} ────────────
  │ ◀── node generate end {chars:386} ─────
  │ ◀── node grade_generation start ───────
  │ ◀── node grade_generation end {grounded:yes,...}
  │ ◀── message_end {message:{id:102,sources,trace}}
```

若发生改写，`node transform_query` 与第二次 `retrieve`、`grade_documents` 会依次出现。发生重新生成时，`node generate` 会再出现一次，`chunk` 会重新累积，前端需要把上一段未确认的流式内容清掉再重画，避免重复文本。

### 5.5 约束与错误

| 场景 | 行为 |
|---|---|
| 空内容 | `error` 400，消息不入库 |
| 超过 2000 字符 | `error` 400 |
| 会话已关闭 | `error` 400，提示刷新新建会话 |
| 同一连接已有进行中的提问 | `error` 409 `chat_busy`，不排队 |
| 会话限流 | `error` 429，带 `retry_after` |
| 全局并发已满且排队超 3 秒 | `error` 429 |
| 整链路超时 | `error` 504，若有部分生成则先发 `message_end` 再发提示 |
| 服务端未捕获异常 | `error` 500，连接保持 |

### 5.6 断线与重连

前端 `base.js` 里的 `ReconnectingSocket` 沿用 `ai_service` 的实现：30 秒心跳，异常关闭后 3 秒重连，手动关闭不重连。重连成功后前端调 `GET /api/chat/sessions/{id}/messages` 补齐断线期间的消息，再继续接收。服务端重启后 session 仍在，历史不丢。

- `stores/chat.js` 管会话 id、消息数组、流式索引、连接状态、告警文案。

- 令牌过期时清空 `localStorage` 并跳 `/admin` 登录。

## 8. 边界与错误场景

| 场景 | 返回 | 前端处理 |
|---|---|---|
| 空问题 | 400 或 WS error 400 | 输入框不发送，提示补内容 |
| 问题超长 | 400 | 显示字数上限 |
| 会话不存在 | 404 | 重新创建会话 |
| 会话已关闭 | 400 | 锁定输入区，提示刷新 |
| 同一会话并发提问 | 409 `chat_busy` | 禁用发送直至上一条结束 |
| 限流 | 429 带 `Retry-After` | 倒计时提示 |
| 文件重复 | 409 带 `existing_doc_uid` | 提示已存在，可跳转详情 |
| 文件过大 | 413 | 提示压缩或拆分 |
| 类型不支持 | 415 | 提示只收 Markdown |
| 文档未就绪查切片 | 409 | 提示等待入库完成 |
| 任务不存在 | 404 | 刷新列表 |
| 重建冲突 | 409 | 提示已有重建进行中 |
| MySQL 不可用 | 503 | 顶部告警，问答禁用 |
| Milvus 不可用 | 问答自动降级为联网，不报 503 | trace 中显示检索失败 |
| 大模型超时 | 抽取式兜底或 504 | 展示原文片段与提示 |
| 令牌过期 | 401 | 重新登录 |

## 9. 兼容性与演进

- 字段只增不减。前端解析响应时忽略未知字段，服务端新增 `verified`、`trace.detail` 这类字段不会破坏旧页面。
- 枚举值只增不改。`source` 后续可能增加 `cache`，`task_type` 可能增加 `migrate`，前端遇到未知值显示原始字符串，不报错。
- WebSocket 事件按 `type` 分发，未知 `type` 直接忽略，便于服务端先上线新事件。
- 若未来启用 `/api/v1`，`GET /api/meta` 会返回新版本号，旧路径保留一个版本周期。
- 管理端令牌方案是演示级，演进到生产时换成 JWT 加刷新令牌，接口头名保持不变，前端改动最小。
